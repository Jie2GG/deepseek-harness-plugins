# GitHub CLI

在 Harness 设置面板中新增 **GitHub** 页面，管理这台 Host 上的 GitHub CLI（`gh`）。
页面上有两块：一块管 `gh` 已登录的账号，一块管 `gh` 这个程序本身。

入口：侧边栏底部 → **设置 → GitHub CLI**。

## 账号管理

- 列出 `gh` 记录的所有主机与账号：当前生效账号有标记，同时显示权限范围（scopes）、
  凭证存储方式和记录的 git 协议。
- **用浏览器登录** 会启动 `gh auth login --web`，一旦 `gh` 打印出一次性代码就立刻显示
  代码和链接，你可以在任意设备上完成验证；页面持续轮询，直到登录成功、失败或被你取消。
- **用令牌登录** 把你粘贴的个人访问令牌交给 `gh auth login --with-token`。令牌不显示、
  也不由本插件保存，仍存放在 `gh` 自己的凭证库里。
- 某台主机有多个账号时，**设为当前** 可切换生效账号；**登出** 需要就地二次确认。
- **复制令牌** 只在点击这一刻向 Host 请求该账号的当前令牌并写入剪贴板，页面其他地方不会
  把它显示出来。

## 安装管理

- 显示本插件解析到的 `gh` 路径、版本，以及这个路径是来自插件自身配置还是来自 `PATH`。
- **检查更新** 从 api.github.com 读取 `cli/cli` 的最新 Release（已登录时会带上 `gh` 令牌，
  避免触发限流），并与当前生效版本比较。
- **安装最新版** 下载本机架构对应的官方 Linux tar 包，用 Release 里的
  `checksums.txt` 校验 sha256，再用 `tar` 解压，安装到
  `~/.local/share/dsh-plugin-github/bin/gh`（遵循 `XDG_DATA_HOME`），随后把本插件指向该
  副本，并确认新程序可以运行。
- **删除托管副本** 只删这个属于插件的文件。
- **gh 路径** 输入框会通过 profile patch 层写入插件自身配置，因此保存会重启插件；
  **改用 PATH 上的 gh** 则清空该配置。

## 配置

bundle 插入的行是 `id: github`。配置可在 profile patch 中编辑，页面的路径输入框也会替你改
`command`：

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `command` | `gh` | 每次调用 `gh` 使用的程序名或绝对路径。 |
| `timeoutMs` | 30000（1000–300000） | 单次 `gh` 调用的时限。 |
| `maxOutputBytes` | 65536（1024–4194304） | 每条 `gh` 输出流捕获的字节数。 |

## 边界

- 本插件从不调用 apt、dnf 或 Homebrew。macOS、Windows，以及没有官方 tar 包的 Linux
  架构上，它只会说明情况，把安装留给系统包管理器。
- 除上面列出的账号与状态调用外，它不会替你执行其他 `gh` 命令，本轮也还没有注册 agent 工具。
- 不提供 `gh auth refresh` 之类需要终端的交互；插件启动子进程时会禁用交互提示，卡住的提示
  会直接失败而不是挂住。
- 插件启动的子进程继承的是被清理过的环境变量，`GH_TOKEN`、`GITHUB_TOKEN` 不会自动透传给
  `gh`；`gh` 已使用的 keyring 或配置文件凭证不受影响。
- 所有动作都在 Host 上执行，只有由同一个 Host 提供的页面能够调用。
