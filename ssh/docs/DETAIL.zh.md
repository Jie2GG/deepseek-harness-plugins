# SSH 管理

管理「本机要连的 SSH 目标」：一份命名清单（主机名或已有的 OpenSSH 别名）、每条目标
连接时使用的参数，以及在浏览器里就能跑的连通性测试。0.2.0 版交付这个页面；agent 暂时
还不会替你执行任何操作。

## 页面在哪里

打开**设置**，在左侧导航选择 **Remote connections**（中文界面即「远程连接」）。导航项
带自己的图标，文案跟随你在「通用」里选择的语言。

## 0.2.0 版做什么

- **SSH 目标清单**：新增、编辑、删除命名目标。每条包含显示名称、主机名或已有的 OpenSSH
  别名，可选远端用户、端口、私钥文件、跳板主机、额外的 `ssh` 参数（每行一个 argv
  参数）与备注。清单最多 64 条。
- **连通性测试**：`测试` 对单条目标做一次探测；`全部测试` 一轮覆盖前 12 条。探测命令是
  `ssh -o BatchMode=yes -o ConnectTimeout=<n> … <主机> true`，因此不会等待输入口令，也不
  会在远端执行除 `true` 以外的命令。结果会被归类为：可连通、认证失败、无法连接、主机密钥
  未信任、探测超时、找不到 ssh；最近一次结果连同时间与输出片段会被保留。
- **客户端参数**：`ssh` 可执行文件（PATH 中的名字或绝对路径）、探测超时、捕获输出上限。

## 数据存在哪里

数据归插件自己所有：清单与参数存在插件自己的存储域 `ssh_targets`，Host 默认后端把它写成
`$DSH_HOME/storages/ssh_targets.json`。profile 的 `cordis.patch.yml` 里只有这个 bundle
插入的那一行插件条目，因此在页面上保存既不会改写你的 patch 文件，也不会重启插件。

两点需要知道：

- 删除插件后，那份 JSON 会留在原地，直到你自己清理。
- 备份数据时要覆盖 `$DSH_HOME/storages/`，只备份 patch 文件是不够的。

页面不保存也不显示任何机密，私钥只以路径引用。

## 页面从不改动的东西

- `~/.ssh/config`、密钥、agent socket：只由 `ssh` 自己读取，插件从不写入。
- `known_hosts`：探测保持 OpenSSH 的严格主机密钥校验，未被信任的主机会被如实报告而不是
  被顺手接受。想记录密钥请在终端手动连接一次。
- `ssh` 程序本身：不安装、不升级，找不到就作为一种结果报告出来。

## 计划中的行为

1. 给 agent 一个工具，复用同一批操作，让模型能问「这台机器通不通」并执行受限的远程命令。
2. 在主机与命令白名单下执行远程命令。
3. 私钥口令存进 Harness 凭据库，不落文件。
4. 读取 `~/.ssh/config` 里的别名作为建议清单。

以上均未实现，接口仍可能调整。

## 配置

bundle 插入一行 `config: {}` 的插件条目，0.2.0 没有声明任何配置字段：页面上编辑的所有内容
都存在插件自己的存储里。你现在往那一行加的键都会被忽略。

## 本版本限制

- 只有设置页这一个界面，agent 还看不到也用不了这份清单。
- 探测只能用「非交互式 ssh 当下就能用上的凭据」：ssh-agent，或无口令私钥。
- 页面需要 Host 的 `/api` 载体、subprocess provider 与存储域设施；缺任意一项的 profile 里
  插件保持未激活，而不是报错。
- 除设置页外没有其它 Web UI 挂载。
