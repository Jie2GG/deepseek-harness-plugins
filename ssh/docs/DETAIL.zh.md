# SSH 管理

管理「本机要连的 SSH 目标」：一份命名清单（主机名或已有的 OpenSSH 别名）、每条目标
连接时使用的参数，以及在浏览器里就能跑的连通性测试。**0.6.0** 起，对话也能直接用这台
服务器：agent 多了一个 `ssh_client` 工具，可以执行命令、列目录、读写文件，并用 `scp` 上传
下载——全部作用在你为这个会话选好的目标上，用的就是本页存的凭据。两边都不会安装或升级
任何程序。
## 页面在哪里

打开**设置**，在左侧导航选择 **Remote connections**（中文界面即「远程连接」）。导航项
带自己的图标，文案跟随你在「通用」里选择的语言。页面顶部有两个选项卡：

- **SSH 目标清单**：新增、编辑、删除与测试。
- **客户端参数**：`ssh` 可执行文件、探测超时、所有探测共用的输出上限，以及插件写在代码
  里的固定边界。

两个选项卡共用同一份页面状态，所以在第一个选项卡上发起的探测，切到第二个选项卡时仍在
继续。

## 当前版本做什么

- **SSH 目标清单**：新增、编辑、删除命名目标。一个输入框就能写下地址——
  `[user@]host[:port]`、`ssh://` 写法、方括号里的 IPv6，或只写名字（按已有的 OpenSSH
  别名理解）；跳板主机、额外 `ssh` 参数（每行一个 argv 参数）与备注收在折叠的「高级
  选项」里。显示名称可以不填，留空时用地址充当名称。清单最多 64 条。
- **每条目标可以「解析」**：点一下会问本机 OpenSSH 客户端这个地址实际等于什么——要连的
  主机、端口、用户、会按顺序尝试的身份文件、跳板或 `ProxyCommand`——整个过程不联网。若解析
  结果和你保存的不一致，会有一个标记说明，因为这正是「我终端里好用、这里不好用」的常见原因：
  解析用的是跑探测的那个账号的配置。
- **两种登录方式**：选 **密钥**（ssh-agent 或私钥，私钥带口令时再填口令框）或 **密码**
  （不再提供 publickey）。方式按目标各自保存，并在清单行上显示。0.4.0 提供的
  **密钥 + 密码**已从选择器里去掉：已经存成该方式的目标仍会显示旧标签，探测行为也与之前
  完全一致，只是不能再被选中或写入。
- **连通性测试**：`测试` 对单条目标做一次探测；`全部测试` 一轮覆盖前 12 条。探测用这条
  目标自己的参数与凭据连接，远端只执行 `true`：纯密钥方式保持 `BatchMode=yes`，不会等待
  输入；需要凭据的方式改由插件自带的 askpass 助手应答提示，并且只允许提示一次。结果会被
  归类为：可连通、认证失败、无法连接、主机密钥未信任、探测超时、找不到 ssh；最近一次结果
  连同时间与输出片段会被保留。
- **客户端参数**在第二个选项卡：`ssh` 可执行文件（PATH 中的名字或绝对路径）、探测超时、
  捕获输出上限；该选项卡同时列出插件写死在代码里的固定边界。

## 在对话里怎么用

直接说就行。agent 可调用的清单里已经写着每台服务器的别名和它实际连到哪，它会按你这段话的意思挑
一台传进去；能执行命令、读目录或文件、精确替换文件里的一段文本、写入、上传下载。一旦它点名了某台，这个会话之后就用那台，所以
「再看看磁盘占用」这种追问不必重复主机名。增删目标之后，下一轮对话里 agent 看到的可选项就跟着变，
不用重启会话。

两个容易混在一起的开关：工作区的**完全权限**只管写盘有多自由，**会不会弹审批**是另一回事——
一个设成「从不询问」的会话会把任何请求都记成拒绝，而且是在有人能表态之前就把这事定死了。所以在
那种会话里，插件不会再替你把需要确认的操作拒掉，而是直接执行；把某台目标的 **agent 访问**关掉
仍然是硬拒绝，而会问你的会话照旧会先弹确认。

哪些会直接执行、哪些要先问你：

| 这次调用 | 结果 |
| --- | --- |
| 列目录、读文件、下载，或问「这轮要用哪台服务器」（`get_connection`） | 直接执行 |
| 命令的首个程序在该目标的**命令白名单**里，或该目标根本没设白名单 | 直接执行 |
| 精确替换远端文件里的一段文本（匹配不唯一就拒绝） | 先弹确认 |
| 其它任何命令，以及写入或上传 | 先弹确认，用你的语言写清服务器和具体命令或路径 |
| 目标是 **agent 访问关闭**的 | 直接拒绝 |

白名单里写的是裸程序名（`git`、`systemctl`）；只要有管道、重定向或替换，就不算单个程序，
一定会拿来问你。没有审批界面的 profile 会把需要询问的调用拒掉，而不是默默执行。

本地文件只能待在这个会话自己的工作区：路径在工作区之外，或者用 `..` 走出去，都会在真正
动手之前被拒绝。

## 数据存在哪里

数据归插件自己所有：清单与参数存在插件自己的存储域 `ssh_targets`，Host 默认后端把它写成
`$DSH_HOME/storages/ssh_targets.json`。profile 的 `cordis.patch.yml` 里只有这个 bundle
插入的那一行插件条目，因此在页面上保存既不会改写你的 patch 文件，也不会重启插件。

两点需要知道：

- 删除插件后，那份 JSON 会留在原地，直到你自己清理。
- 备份数据时要覆盖 `$DSH_HOME/storages/`，只备份 patch 文件是不够的。
- 同一个文件里还记着每个会话选了哪台目标；删掉一条目标，指向它的会话选择会一起清掉。

## 密码与私钥口令

登录用的机密存在 Harness 凭据库——私有文件 `$DSH_HOME/.credentials.yaml`，权限只允许
属主读——地址形如 `ssh/<目标>-password` 与 `ssh/<目标>-passphrase`。它不进插件自己的
JSON，不进 profile 的 patch 文件，也不会回传到浏览器：

- 凭据输入框留空表示「保留已存的值」，勾选「忘掉已保存的值」才会删除。
- 清单只显示某一项是否已存，从不显示内容。
- 删除目标会同时忘掉它的两项凭据。
- 在尚未保存的表单里输入的密码只被「保存前先测试」用一次，只有你点了保存才会入库。
- `ssh` 通过插件自带的 askpass 助手读取机密，而不是终端或命令行，因此它不会出现在进程
  列表里；私钥本身仍只以路径引用。

两点实话实说的限制：这个存储文件对你的操作系统用户是可读的，而 agent 的工具进程正是以
同一个用户运行，所以存的机密是「对其他用户私密」而不是「对 agent 隐藏」。另外，即便已存
了密码，探测在远端也只执行 `true`——插件目前不在远端跑别的命令。

## 终端能连、页面说连不上，是为什么

探测不是你终端里的那次会话。它以 Harness Host 进程所属的账号运行，「客户端参数」选项卡
里的「探测运行身份」会写出那个账号。该账号有自己的一套 `~/.ssh/config`、私钥、
`ssh-agent` 与 `known_hosts`，因此：

- 你终端里好用的别名，对 Host 账号可能指向别的机器，或者根本解析不到；
- 你在自己 shell 里通过 agent 用到的密钥，并不在那个 agent 里；
- 你在终端里手动信任过的主机，那边并不会因此就被信任——首次探测是把它**记录**下来，而不是
  提问。

已存密码那条路不依赖上面这些，它自己就能完成认证；这也正是 0.5.1 把「未知主机密钥」从
一个没人能回答的提问变成一条自动记录的原因。

## 页面从不改动的东西

- `~/.ssh/config`、密钥、agent socket：只由 `ssh` 自己读取，插件从不写入。
- `known_hosts`，除了一点：未知的主机密钥会在**首次联系时自动记录**
  （`StrictHostKeyChecking=accept-new`），因为探测没有终端可以提问，否则它会一直等下去。
  主机密钥**发生变化**时仍然会被拒绝，不会被顺手覆盖。
- `ssh` 程序本身：不安装、不升级，找不到就作为一种结果报告出来。

## 计划中的行为

1. 可交互或长时间的远程会话（PTY，或对话能轮询的后台任务），让需要输入、或者一条回复
   等不完的命令也能用。
2. 按目标显示 `ssh -G` 解析出的实际参数（用户、端口、身份文件），好让人核对别名到底连的
   是什么。
3. 读取 `~/.ssh/config` 里的别名作为建议清单。

以上均未实现，接口仍可能调整。
## 配置

bundle 插入一行 `config: {}` 的插件条目，本版本没有声明任何配置字段：页面上编辑的内容要么
存在插件自己的存储里，要么存在 Harness 凭据库里。你现在往那一行加的键都会被忽略。

## 本版本限制

- 远程命令是一次性等结果的：没有交互会话、没有 PTY、也没有可轮询的后台任务，需要从终端
  取输入的命令会一直等到超时。
- 设置页上的探测仍然只在远端跑 `true`；真正执行命令的是 agent 的 `exec` 动作。
- 插件包被就地替换后，正在运行的 Harness 会沿用旧的 Host 模块直到重启：重启之前 agent 还
  没有 `ssh` 工具，新的超时与上限也未生效。设置页与输入区那一行属于浏览器侧，会自己更新。
- 下载回来的文件会像被编辑过的工作区文件一样，出现在这轮对话的改动清单里：插件在复制开始
  之前先向文件系统管线申请许可。注意一个路径只在一轮里的第一次改动会留下改动前的快照，而子
  agent 的会话不在记录范围内。
- `write` 与 `upload` 就地替换文件：服务器上没有版本或回滚，目录下载需要显式递归。
- 页面需要 Host 的 `/api` 载体、subprocess provider、存储域设施、凭据库、工具注册表，以及
  已挂载的文件系统与工作目录服务；缺任意一项的 profile 里插件保持未激活，而不是报错。
- 界面只有这一页设置（含两个选项卡）；对话里的能力走 `ssh_client` 工具，调用记录用宿主默认的
  工具行显示，跟别的工具一致；输入区不再放服务器选择菜单。
