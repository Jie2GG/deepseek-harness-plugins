# SSH 管理

管理「本机要连的 SSH 目标」：一份命名清单（主机名或已有的 OpenSSH 别名）、每条目标
连接时使用的参数，以及在浏览器里就能跑的连通性测试。对话也能直接用这台
服务器：agent 多了一个 `ssh_client` 工具，可以执行命令（跑很久的还能挂到后台，之后再接
着读输出、随时叫停）、列目录、读写文件、按精确文本替换文件里的一段内容，并用 `ssh` 通道上传
下载——全部作用在你为这个会话选好的目标上，用的就是本页存的凭据。两边都不会安装或升级
任何程序。

## 页面在哪里

打开**设置**，在左侧导航选择 **Remote connections**（中文界面即「远程连接」）。导航项
带自己的图标，文案跟随你在「通用」里选择的语言。页面顶部有两个选项卡：

- **SSH 目标清单**：新增、编辑、删除与测试。
- **客户端参数**：输出上限、命令超时、传输上限三个覆盖框，旁边是这个 profile 实际
  解析出来的边界（每个上限都写成「生效 / 默认 / 上限」）。

两个选项卡共用同一份页面状态，所以在第一个选项卡上发起的探测，切到第二个选项卡时仍在
继续。

## 当前版本做什么

- **SSH 目标清单**：新增、编辑、删除命名目标。一个输入框就能写下地址——
  `[user@]host[:port]`、`ssh://` 写法、方括号里的 IPv6，或只写名字（按已有的 OpenSSH
  别名理解）；跳板主机、额外 `ssh` 参数（每行一个 argv 参数）与备注收在折叠的「高级
  选项」里。显示名称可以不填，留空时用地址充当名称。清单最多 64 条。
- **每条目标可以「解析」**：点一下会问本机 OpenSSH 客户端这个地址实际等于什么——要连的
  主机、端口、用户、会按顺序尝试的身份文件、跳板或 `ProxyCommand`——整个过程不联网。若解析
  结果和你保存的不一致，会有一个标记说明，因为这正是「我终端里好用、这里不好用」的常见原因：
  解析用的是跑探测的那个账号的配置。
- **两种登录方式**：选 **密钥**（ssh-agent 或私钥，私钥带口令时再填口令框）或 **密码**
  （不再提供 publickey）。方式按目标各自保存，并在清单行上显示。早期版本提供的
  **密钥 + 密码**已从选择器里去掉：已经存成该方式的目标仍会显示旧标签，探测行为也与之前
  完全一致，只是不能再被选中或写入。
- **连通性测试**：`测试` 对单条目标做一次探测；`全部测试` 一轮覆盖前 12 条。探测用这条
  目标自己的参数与凭据连接，问的就是「这条凭据能不能把已登录的会话建立起来」：走共享连接的
  目标只把连接开到登录成功就收（`-N`，实测首次两百分之一秒、连接还热着时十分之一秒），没走
  共享连接的目标仍旧在远端只执行 `true`。纯密钥方式保持 `BatchMode=yes`，不会等待输入；需要
  凭据的方式改由插件自带的 askpass 助手应答提示，并且只允许提示一次。一次探测最多等固定的
  三十秒，其中拨号占三分之一（最多十秒），所以没人应答的主机还是很快就失败。结果会被归类为：
  可连通、认证失败、无法连接、主机密钥未信任、探测超时、找不到 ssh；最近一次结果连同时间与
  输出片段会被保留。
- **连接是复用的**：同一台服务器上，第一条命令开好的连接会留在插件手里，之后的调用搭同一条
  连接——不再每条命令都重新握手、重新登录，服务器那边也只剩一个 `sshd` 在为你干活。能同时
  留着 8 台服务器，每台在最后一次调用之后空闲 5 分钟就自己断开。有些服务器在多条命令共用一条
  连接时行为不一样，那种就在该目标的「高级选项」里关掉「复用这台服务器的连接」。
- **客户端参数**在第二个选项卡：捕获输出上限、agent 每条远程命令都要遵守的命令超时，
  以及一次复制不许越过的传输上限。这三个框现在只是**这个 profile 的覆盖**：留空表示跟
  配置里的默认走，填正数都收，超过上限会被夹住并回显生效值。用哪个程序拨号仍然不是设置
  项：`ssh` 与 `scp` 由插件自行探测（先找 PATH，再试常见安装位置）。旁边的卡片从
  「固定边界」改叫**「解析后的边界」**：每个上限都写成「生效 / 默认 / 上限」三段，让人
  一眼看见这次到底按哪个数跑；另有几条是这台 Host 的固定规则——能同时在跑的远程操作数、
  可以各留一条连接的目标数上限、一条共享连接空闲多久后断开、「全部测试」一轮覆盖几条、
  探测等多久（三十秒；下载前那次「这文件多大」另算十秒）。

## 在对话里怎么用

直接说就行。agent 可调用的清单里已经写着每台服务器的别名和它实际连到哪，它会按你这段话的意思挑
一台传进去；能执行命令、读目录或文件、精确替换文件里的一段文本、写入、上传下载，也能把跑很久
的命令丢到后台，之后分段读它的输出、随时叫停。命令还可以提权执行：以其他账户通过 sudo 运行
（插件用这台目标存好的登录密码应答 sudo），或在没有 sudo 的机器上用 su 切到 root（用第三个
凭据槽——root 自己的密码——应答，密码在目标表单里保存）。无论哪种，密码都是插件在幕后注入的，
永远不会出现在对话里。提权提示和 `input` 正文抢的是同一条 stdin，而且提示先读——所以 su 带
input 会被直接拒绝，as 带 input 且这台存了登录密码时也一样；唯一能共处的组合是没存登录密码的
as（走 `sudo -n`，永不弹提示，正文原样送达）。目标点名了私钥时，插件会带上
`-o IdentitiesOnly=yes`：ssh-agent 里的其他密钥不会抢先把服务器的认证次数烧光；不点名私钥就
什么都不加，客户端自己的默认规则照旧。一旦它点名了某台，这个会话之后就用那台，所以
「再看看磁盘占用」这种追问不必重复主机名。增删目标之后，下一轮对话里 agent 看到的可选项就跟着变，
不用重启会话。

两个容易混在一起的开关：工作区的**完全权限**只管写盘有多自由，**会不会弹审批**是另一回事——
一个设成「从不询问」的会话会把任何请求都记成拒绝，而且是在有人能表态之前就把这事定死了。所以在
那种会话里，插件不会再替你把需要确认的操作拒掉，而是直接执行；把某台目标的 **agent 访问**关掉
仍然是硬拒绝，而会问你的会话照旧会先弹确认。反过来，**没有**审批服务的 profile（或服务没挂、
这次调用找不到可路由的会话）不算这种「明示过的常备决定」：询问照样发给核心，由核心给出写明
缺口的拒绝——没人能点头，不等于有人点过头。

哪些会直接执行、哪些要先问你：

| 这次调用 | 结果 |
| --- | --- |
| 列目录、读文件、下载，或问「这轮要用哪台服务器」（`get_connection`） | 直接执行 |
| 提权执行的命令（sudo 切账户，或 su 切 root） | 一定先问你——即使命令本身在白名单里；确认框会写明以哪个身份执行、将动用哪个已存密码 |
| 命令只有一个裸程序，且它在目标的**命令白名单**里 | 直接执行 |
| 精确替换远端文件里的一段文本（匹配不唯一就拒绝） | 先弹确认 |
| 其它任何命令，以及写入或上传 | 先弹确认，用你的语言写清服务器和具体命令或路径 |
| 目标是 **agent 访问关闭**的 | 直接拒绝 |

新建目标的白名单是空的，这种情况下**每一条**命令都会先问你；**agent 访问**开关和白名单都在目标
表单里编辑（关掉访问会在清单行上挂一个徽章，白名单非空时也有计数徽章）。白名单是**免审批名单**，
不是沙箱、也不是限制器：列进 `git` 只是让裸 `git …` 不再打扰你，不约束它拿到什么参数。白名单里
写的是裸程序名（`git`、`systemctl`）；只要有管道、重定向或替换，就不算单个程序，一定会拿来问你。
没有审批界面的 profile 会把需要询问的调用拒掉，而不是默默执行。

本地文件只能待在这个会话自己的工作区：路径在工作区之外，或者用 `..` 走出去，都会在真正
动手之前被拒绝。

## 数据存在哪里

数据归插件自己所有：清单与参数存在插件自己的存储域 `ssh_targets`，Host 默认后端把它写成
`$DSH_HOME/storages/ssh_targets.json`。profile 的 `cordis.patch.yml` 里只有这个 bundle
插入的那一行插件条目，因此在页面上保存既不会改写你的 patch 文件，也不会重启插件。

两点需要知道：

- 删除插件后，那份 JSON 会留在原地，直到你自己清理。
- 备份数据时要覆盖 `$DSH_HOME/storages/`，只备份 patch 文件是不够的。
- 同一个文件里还记着每个会话选了哪台目标；删掉一条目标，指向它的会话选择会一起清掉。

## 密码与私钥口令

登录用的机密存在 Harness 凭据库——私有文件 `$DSH_HOME/.credentials.yaml`，权限只允许
属主读——地址形如 `ssh/<目标>-password` 与 `ssh/<目标>-passphrase`。它不进插件自己的
JSON，不进 profile 的 patch 文件，也不会回传到浏览器：

- 凭据输入框留空表示「保留已存的值」，勾选「忘掉已保存的值」才会删除。
- 清单只显示某一项是否已存，从不显示内容。
- 删除目标会同时忘掉它的三项凭据。
- 还有第三个槽存 **root 自己的密码**：只有 agent 用 su 提权时才会动用它；sudo 用的是登录
  密码。它与前两者遵循完全相同的规则。
- 在尚未保存的表单里输入的密码只被「保存前先测试」用一次，只有你点了保存才会入库。
- `ssh` 通过插件自带的 askpass 助手读取机密，而不是终端或命令行，因此它不会出现在进程
  列表里；私钥本身仍只以路径引用。命令提权时，密码是作为该命令自己的标准输入穿过已加密
  的通道的——对话、记录、进程表里都看不到它。

两点实话实说的限制：这个存储文件对你的操作系统用户是可读的，而 agent 的工具进程正是以
同一个用户运行，所以存的机密是「对其他用户私密」而不是「对 agent 隐藏」。另外，页面上
自己的连通性测试只把连接开到登录成功为止（关掉复用的目标才会顺带跑一次 `true`）；对这些凭据更宽的使用——命令、编辑、传输——都
发生在对话里，走上表那套确认规则。

## 终端能连、页面说连不上，是为什么

探测不是你终端里的那次会话。它以 Harness Host 进程所属的账号运行——也就是启动 Harness
的那个账号，未必是你敲 `ssh` 的那个——而该账号有自己的一套 `~/.ssh/config`、私钥、
`ssh-agent` 与 `known_hosts`，因此：

- 你终端里好用的别名，对 Host 账号可能指向别的机器，或者根本解析不到；
- 你在自己 shell 里通过 agent 用到的密钥，并不在那个 agent 里；
- 你在终端里手动信任过的主机，那边并不会因此就被信任——首次探测是把它**记录**下来，而不是
  提问。

已存密码那条路不依赖上面这些，它自己就能完成认证；这也正是插件把「未知主机密钥」从
一个没人能回答的提问变成一条自动记录的原因。

## 页面从不改动的东西

- `~/.ssh/config`、密钥、agent socket：只由 `ssh` 自己读取，插件从不写入。
- `known_hosts`，除了一点：未知的主机密钥会在**首次联系时自动记录**
  （`StrictHostKeyChecking=accept-new`），因为探测没有终端可以提问，否则它会一直等下去。
  主机密钥**发生变化**时仍然会被拒绝，不会被顺手覆盖。
- `ssh` 程序本身：不安装、不升级，找不到就作为一种结果报告出来。
- 复用用的控制套接字：不在 `~/.ssh` 里，也不进 `$DSH_HOME`。它存在插件自己开的私有临时
  目录里（权限只许属主读写），插件卸载时连同目录一起删掉，因此既不用备份也不会留下来。

## 计划中的行为

1. 能实时敲字的终端：已经可以给命令要一个伪终端（`tty`）、把答案直接递给它（`input`），
   也能把长命令丢进对话可轮询、可随时叫停的后台任务——但还没有一个实时交互的会话。
2. 读取 `~/.ssh/config` 里的别名作为建议清单。

以上尚未实现，接口仍可能调整。旧清单排头的两项——可轮询的后台任务与 `ssh -G` 解析
视图——均已在此前的迭代中落地。

## 配置

bundle 插入的那一行现在**会读** `config:` 里的键了。每个可调的量都是一对「默认值 +
封顶值」，全部是热更新（改了就走下一条调用，不用重启）：

| 键 | 默认 | 封顶默认 | 管什么 |
| --- | --- | --- | --- |
| `timeoutMs` / `maxTimeoutMs` | 30 秒 | 300 秒 | 一条前台远程命令的时限，与任何来源（页面、目标、单次调用）都能要到的最大值 |
| `outputBytes` / `maxOutputBytes` | 64 KiB | 4 MiB | 每条流（stdout、stderr 各一份）留在内存里的上限 |
| `transferBytes` / `maxTransferBytes` | 32 MiB | 512 MiB | 一次复制的字节上限 |
| `probeTimeoutMs` | 30 秒 | — | 一次连通性测试最多等多久（页面上没有这个框）；自 0.0.37 起，页面遇到不返回 bounds 的老 Host 时用的兜底值也是这 30 秒（0.0.36 展示的是 10 秒，而 Host 从 0.0.23 起就一直在按 30 秒拨号） |
| `transferTimeoutMs` / `maxTransferTimeoutMs` | 5 分钟 | 30 分钟 | 一份复制里**每个远端子进程**的时限，走自己的钟：传输不再借用命令的 30 秒；复制类调用里的 `timeoutMs` 读作「愿意等这一次复制多久」。上传会有多个这样的子进程（预检查、复制、落地），所以每步都等到期限的一次调用，实际可能跑到该数字的好几倍才回答——实测 1.5 秒的调用用了 3.65 秒 |
| `maxTransferFiles` | 500 | — | 递归上传预检查的文件数上限（按遍历那一刻的统计） |
| `maxTransferTotalBytes` | 512 MiB | — | 递归上传预检查的累计字节上限（同样是遍历时刻的数） |
| `maxConcurrentTransfers` | 2 | 16 | 同时最多几条复制占用 16 个执行槽——传输不许饿死命令；槽位满而被拒的复制按普通 `failed` 结果回答，`message` 里点明是哪条通道 |
| `maxRunningJobs` | 8 | 8 | 显式后台任务最多占几个槽。这个封顶值不是可选的：16 个执行槽里有 8 个是给「会等人的调用」留的，配置超过就报错，旧配置里还写着更大值时 `bounds.ts` 会夹回来并在 note 里说明（页面显示夹后的值），`transport.ts` 在真正领槽位时再夹一次 |
| `statTimeoutMs` | 10 秒 | — | 复制动手前那次「这文件多大」的时限 |
| `maxSpillBytes` | 64 MiB | — | 溢出文件能写多大；填 0 表示不落溢出文件（结果里会明说没有文件可找）。每 Host 进程的落盘预算也可能先停下来，并会写明 |
| `promoteOnTimeout` | 开 | — | 前台命令跑到时限时改成后台任务继续跑，而不是把进程杀掉 |
| `graceMs` | 2 秒 | — | 子进程 SIGTERM 到 SIGKILL 之间的宽限 |

两点要说明。第一，页面上那三个框现在只是**这个 profile 的覆盖**：留空就是「跟配置里的
默认走」，填任何正数都收——超过封顶值会被**夹住**，并且把真正生效的值回显给你，而不是
像以前那样把数拒绝掉。第二，把 `maxTimeoutMs` 抬到 300 秒以上时，插件向 harness 声明的
**工具调用预算**是注册时定下的，要重启 Host 才会跟上；在那之前，超过旧预算的等待会先被
harness 那句 `tool call timed out` 掐掉。

## 本版本限制

- 复用出来的主连接是 `ssh` 自己转到后台的进程，不是插件还盯着的子进程。插件卸载时会关掉它认得的
  主连接；Host 被直接杀掉时，服务器那侧的会话会一直留到 5 分钟空闲到点。池子属于 Host 进程，
  不属于某个会话：两个对话连的是同一台服务器，就共用同一条连接——这是它的作用，也是为什么经跳板机
  连的服务器会被另一个对话「捂热」。
- 前台的远程命令默认还是一次性等结果的：没有一个能实时敲字的终端。需要终端的命令可以要一个
  （`tty: true`），需要输入的命令也能直接把答案递进去（`input: "…"`）。跑得很久的命令可以用
  `background: true` 丢到后台，立刻拿到任务 id，之后用 `job_output` 接着读、用 `job_kill` 停掉；
  后台任务**没有自带的寿命上限**——它活到自己结束、被 `job_kill`、所属对话消失、或 Host 退出，
  这期间一直占着插件十六条并发操作槽里的一条。前台命令跑到时限也不再被杀：默认会把还在跑的
  那条**转成交给后台**，回一个 `status=promoted` 加任务 id，并把截止前已经产出的部分一起给你
  （那不叫「被截断」——流还在写，`job_output` 从开头都能读到）；提权的命令同样能转，密码早在
  spawn 时就注进去了）；如果这个对话的后台名额已经满了，就退回原来的
  杀进程，并在结果里说明是哪一种。权限判断跟前台
  执行完全一样。还缺的是「能实时对话的终端」，以及「这个会话结束后仍在服务器上活着
  的命令」——后者要靠 `nohup` 或 systemd 单元，`exec` 可以帮你写出来。提权（`as`/`su`）
  是前台能力——后台任务没有接收密码的通道——不过服务器配了 NOPASSWD 时，命令里自己写
  `sudo` 在后台照样能用。
- 设置页上的探测只到登录为止：它不跑你的命令，因此也说不出远端 shell 是否坏掉（只有关掉复用
  的目标会顺带跑一次 `true`）。而且共享连接还热着时，探测是直接答「可连通」——它验的问题变了：
  「这条凭据现在有没有一条已登录的连接」。凭据一改，套接字名字跟着变，下一次探测必然重新登录。
  真正执行命令的是 agent 的 `exec` 动作。
- 插件包被就地替换后，正在运行的 Harness 会沿用旧的 Host 模块直到重启：重启之前 agent 还
  没有 `ssh` 工具，新的超时与上限也未生效。设置页与输入区那一行属于浏览器侧，会自己更新。
- 超界的输出不再是「丢了尾巴就算了」：这条命令的完整 stdout / stderr 会被写进 provider
  自己那份私有临时目录里的溢出文件，结果里直接给路径（`[output truncated; full output —
  stdout: /tmp/dsh-subprocess-…/….log]`）。两种情况例外：profile 把 `maxSpillBytes` 设成
  0（那就明确告诉你没有文件可找），或者整条流比 `maxSpillBytes` 还长（文件到点会被放弃，
  只剩内存里的尾部）。文件在系统临时目录里，由 provider 保管，不在这个会话的工作区。
  这个插件只负责「要不要请求」：每个 Host 进程有一份落盘预算（1 GiB、64 个文件），由
  transport 实例持有，该进程够到的所有服务器共用同一份，不按服务器、也不按会话分账。它是
  **停止授予的阈值，不是硬上限**：授予从不按剩余额度切分（否则provider 装不下的溢出文件会被
  删掉，比一开始没有文件更糟），一个 child 的 stdout 与 stderr 共用同一份授予，所以总量可能
  越过阈值——越过的是触发它的那个 child 加上当时仍在飞的那些，默认最坏接近 3 GiB。阈值过后
  下一条命令只会保留内存里的尾部，并且回答里会写明是预算决定的，不是配置没设好。每个文件
  入账的是 provider 就同一路径回报过的**最大整流向字节偏移**：后台的流会随着文件变长反复重读
  自己的溢出文件，从 0.0.36 起每次更大的上报只补记**差额**（同样大的上报不再计，更小的不退——
  磁盘上的文件不会变小），所以账面跟着真正落盘的字节走，而不是像 0.0.35 那样停在首次上报的数上。
- 下载回来的文件会像被编辑过的工作区文件一样，出现在这轮对话的改动清单里：插件在复制开始
  之前先向文件系统管线申请许可。注意一个路径只在一轮里的第一次改动会留下改动前的快照，而子
  agent 的会话不在记录范围内。
- 单个文件的传输大小上限是**在字节流动的过程中**执行的：计数发生在这一端，复制途中还在
  长大的文件会被当场叫停，回答里报的是「已经过了多少个字节」，而不是「`stat` 当初说过多少
  个字节」。目录仍走 `scp -r`（为的是它的布局与符号链接语义），在动手之前先量一次：上传量
  本地遍历，下载量在服务器上一次枚举；结果里会用 `limitMode` 说明到底是哪一种上限作出了
  回答。落地的方式两个方向都保得住原有文件：下载先写目标旁的临时文件、干净收尾才 rename；
  上传先在服务器上写临时文件，再取最终名字——目标已存在时**透过原文件**写入（inode、mode、
  属主、硬链接全部保留），是新文件时 rename 并带上源文件的权限位（按服务器 umask 过滤）。
  被上限拒绝的上传会删掉自己的临时文件；递归下载若要落地到一个非空目录，会在动手之前就被
  拒绝，而不是先拷完再失败。
  通道满而被拒也是同一类回答：transport 抛 `busy`，复制层把它转成失败结果，
  `message` 说明是哪条通道、`hint` 给出路，一个字节都没动；设置页和直接使用
  transport 的调用方仍看到抛出的错误。复制被叫停时本地的 child 会被等过 TERM→KILL 宽限期
  再退出；从 0.0.36 起复制层还会再发一条简短、有上限、尽力而为的命令，请服务器结束它可能
  留下的滞留进程——卡在「读一个没有写者的 fifo」或「写一个没有读者的 fifo」上的 `cat` 从不
  触碰通道，关掉通道也叫不醒它卡在的那个 syscall（实测曾有这样的 reader 活过它自己的调用好几个
  小时）。**从 0.0.37 起，这个 mover 用一个 pid 点名，不再按路径点名。** mover 卡住之前会先在
  stderr 上打印 `dsh-mover <pid> <tag>`（下载用 `exec` 变成 mover，所以报出的号就是 mover 本身；
  上传落地那步把它放后台、报 `$!`），清理只杀那一个进程——杀之前先按参数逐行读 `/proc/<pid>/cmdline`，
  和本次复制实际传入的 argv 做纯字符串比对。`gone`、`killed`、`killed-unverified`、`foreign`、
  `refused`、`unanswered` 各有一句实话；没拿到 pid 的复制什么都不杀，并说明残留无法指名。0.0.36 的
  `pkill -f '[c]at -- <路径>'` 做不到并发安全：路径正是两个复制同一个文件时唯一共享的东西（真机实测：
  同一 fifo 上两个 parked mover，一次按路径的 `pkill`，零存活），而且远端路径里允许出现 `[`、`*`、`?`、
  `+`、`.`，这些对 `pkill -f` 都是正则语法。新写法不再需要 `pkill` 或 `pgrep`，能清理的服务器反而更宽。
- `edit` 会在一次读取里同时拿到文件内容、它的版本号（inode、大小、纳秒 mtime）**和它的
  SHA-256 摘要**，截断之前先复制备份，就地 `cat >` 写入，再核对写入后应有的字节数**以及本次
  送出字节的摘要**——长度不等于内容：13 个字节可能是这次编辑拼出的 13 字节，也可能是别人写的
  13 字节。中途出错时还有一个修复子进程先看一眼文件再把旧内容放回去，并如实说明发生了哪一种
  结果、依据是什么：`verdict` 由 `digest` 证据支撑，还是只由字节数支撑——只有字节数时一律报
  `unknown`，绝不当成成功；`restored: true` 只在摘要证明放回来的正是本次读到的内容时才给。
  从 0.0.36 起这道摘要校验还挪到了**写入之前**：读取现在还额外报出文件的字节数，让 header 与
  正文的分界按字节定界、而不是猜「哪几行像标记」——文件自己第一行恰好以 `ssh-plugin:` 开头的情况
  再也不会被误剥（K-6）；而当服务器根本给不出 SHA-256（没有 `sha256sum`、`shasum` 或 `openssl`）
  时，编辑会在复制和截断**之前就拒绝**、文件原封不动（K-1），不再像 0.0.35 那样把写入落地后再报
  `unknown`。校验不了的编辑，如今压根不会开始。
  从 **0.0.37** 起，那份字节数不只是「报出来了」，而是**被用上了**：`verifyEditBody` 会在匹配之前、
  dryRun 预览之前，先把切出来的正文和声明的字节数、声明的摘要逐一比对，不一致就拒。这关掉的是 0.0.36
  看不见的正文丢失：不是合法 UTF-8 的文件经 transport 解码后会变成**凭空造出来**的字节（每个解不了的
  字节都变成 `EF BF BD`），编辑再把这串文本写回去——而旧代码手里所有的检查全都通过了：它比的长度是自己
  送出的长度，它验的摘要也是同一串替换字节的摘要。真机 shell 实测：一个以 `FF 41 0A` 开头的文件，按
  0.0.36 的写法替换其中一个 ASCII 词后，那几个字节的总数没变、内容却已被换成 U+FFFD，而结果自称
  `contentVerified: true`。另外，服务器报出的 SHA-256 若不是 64 位十六进制，现在一律按「没有摘要」处理，
  这样的服务器会被拒绝，而不是拿一句关于文件的话去比对。
  「发现改动」与「做出改动」之间的窗口从一次网络往返缩到两条 shell 内建命令，但它仍然是
  窗口：这是确认流，不是事务。`dryRun: true` 只预览匹配数与 diff，不写不备份；服务器给不
  出版本号时预览会说明写入将失去版本校验。被叫停的 `edit` 里，修复步骤不会被同一个取消
  信号杀掉——你取消的是这次编辑，不是「文件要完整」这件事。
- 页面需要 Host 的 `/api` 载体、subprocess provider、存储域设施、凭据库、工具注册表，以及
  已挂载的文件系统与工作目录服务；缺任意一项的 profile 里插件保持未激活，而不是报错。
- 界面只有这一页设置（含两个选项卡）；对话里的能力走 `ssh_client` 工具，调用记录用宿主默认的
  工具行显示，跟别的工具一致；输入区不再放服务器选择菜单。
