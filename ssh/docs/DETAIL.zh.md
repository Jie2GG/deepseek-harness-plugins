# SSH 管理

面向「从当前 Harness Host 所在机器管理 SSH」的插件：本机的 OpenSSH 客户端能连到
哪些主机、配置了哪些别名与身份文件、某台主机是否真的能应答，以及允许 agent 在远端
执行哪些命令，都由这个插件负责。

## 0.1.0 版本做什么

什么都不做。当前版本只是脚手架：插件会被激活，但不注册 agent 工具、不启动进程、
不读取任何 SSH 配置、不打开任何面板。启用或禁用它都不会改变应用里的行为，因此在
能力建设期间可以安全地保留安装。

本轮只把包结构定下来：bundle 清单、patch 条目、展示元信息、图标和详情文档。

## 计划中的行为

后续版本预计按以下顺序补齐：

1. 只读主机清单：OpenSSH 客户端配置里的别名，`ssh -G <主机>` 为每个别名解析出的
   参数（用户、端口、身份文件、跳板），以及 `~/.ssh/known_hosts` 的状态。
2. 连通性探测：在超时限制内执行 `ssh -o BatchMode=yes <主机> true`，把认证失败与
   网络失败分开报告。
3. `run` 动作：在主机白名单与命令白名单、输出与时长限制下，在一台远端主机上执行
   一条命令。
4. 插件配置项：`ssh` 可执行文件名、要读取的配置文件、探测与执行超时、捕获输出上限、
   主机与命令白名单。私钥口令存放在 Harness 凭据库，不放在配置里。
5. 视需要增加 Web UI 面板，复用同一批操作。

以上均未实现，接口仍可能调整。

## 与 Harness 的 SSH 运行时的区别

DeepSeek Harness 本身就带一套 SSH *部署形态*：`@deepseek-ai/dsh-ssh` 与其文件系统、
子进程、沙箱 provider 会让 `ctx.fs` 与 `ctx.subprocess` 指向一台远端机器。这与本插件
是两个维度——本插件保持 Harness 原地不动，只是通过本机 OpenSSH 客户端去访问*别的*
主机。两者不共用配置。

## 配置

bundle 插入一行 `config: {}` 的插件条目。0.1.0 没有声明任何配置字段，此时你在那里
写的键都会被忽略。

## 本版本限制

- 插件不读取也不修改 `~/.ssh/config`、密钥或 agent socket。
- 不存储任何机密，不建立任何连接。
- 不注册任何 Web UI 挂载点。
